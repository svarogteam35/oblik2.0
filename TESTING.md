# Перевірки до запуску

Під час підготовки пакета виконано перевірку синтаксису C# та JavaScript без збірки. З’єднання з базою, SQL-права, роботу API та екрани у браузері не перевірено запуском.

На ізольованому тестовому сервері з копією бази перевірте:

- Новий користувач без дозволу або запрошення не отримує доступ. Реєстрації без адміністратора немає.
- Запрошення одноразове; прострочене не приймається. Після прив’язки потрібні пароль і TOTP. Невірний, прострочений та повторно використаний код не приймається, включно з одночасними запитами.
- Один лише пароль або лише cookie від етапу налаштування MFA не відкриває дані.
- Скидання MFA, закриття доступу, зміна пароля, завершення сеансу і 30 хвилин бездіяльності закривають API.
- Кожна роль бачить лише дозволені фірми та склади. Окремо перевірити головного кладовщика, призначені підсклади, персональні дозволи, вимкнення успадкованих дозволів, приховані батьківські категорії.
- Підміна org/warehouse у запиті не відкриває чужі залишки або плани. Відкликання дозволу набирає чинності на наступному запиті.
- Пошук із лапками, %, _, зворотним слешем та HTML не змінює SQL і не виконує скрипти. Назви товарів показуються звичайним текстом.
- Усі запити зміни стану відхиляються без правильного Origin і CSRF-токена.
- HTTP, невідповідний Host, підроблені forwarded-заголовки та недовірений сертифікат PostgreSQL не приймаються.
- Пароль, MFA-секрет, запрошення і сеанс відсутні в журналах застосунку, проксі та хостингу. Не вмикати журналювання тіл запитів/відповідей входу.
- Окрема роль PostgreSQL не може змінювати складські залишки, права користувачів або видаляти аудит. Протестувати `SELECT ... FOR UPDATE` і всі транзакції входу з виданими мінімальними правами.
- Сервісна панель показує входи, відмови та перегляди. Недоступність бази не відкриває доступ і не розкриває текст винятку.
- Кількість, одиниці, ціна, номери та дати збігаються з настільною програмою; майбутні надходження не входять у поточний залишок.
- Safari на iPhone/Mac: вхід, введення коду, довгі назви, фільтри, перегортання списку та вихід.
- Після перезапуску сервера MFA працює з тим самим захищеним ключем. Резервна копія відновлюється на окремому середовищі.

Результати запуску слід записати тут перед публікацією. Наразі вони не виконані.
